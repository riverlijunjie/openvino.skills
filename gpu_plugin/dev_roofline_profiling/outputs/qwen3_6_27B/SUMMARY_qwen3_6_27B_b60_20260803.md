## 3. Methodology

- **Tool**: cliloader v3.0.6 (Device Performance Timing), average over stable iterations
- **FC decode**: USM_DEVICE activations, 64 MB L3 flush between inferences (prevents L3 weight caching)
- **FC prefill**: Dynamic quantization enabled (INT8 XMX path via `dynamic_quantize_gpu_opt`)
- **PA**: PagedAttention with INT8 KV, block_size=16, NH=24, NKV=4, HD=256
- **GDN**: PagedGatedDeltaNet optimized kernel, cache_interval=0 (decode), cache_interval=T (prefill)
- **Small ops**: 50,000 iterations (decode), 500 iterations (prefill) for stable averages
- **Reported latency**: cliloader kernel average (not host-side timing)
- **swish/multiply**: fused into fc_gate, not profiled separately
- **MTP**: treated as +1 full-attn layer (adds 1 call each to fc_qkv, fc_o, PA, fc_gate, fc_up, fc_down)

## 6. Bottleneck Analysis

### 6.1 Decode Bottlenecks

**Primary bottleneck: Dense FFN weights** (INT4 decode at 91-95% memory BW)
- FFN reads 44.6 MB × 3 (gate+up+down) = 133.8 MB per layer, × 65 layers = 8.7 GB per token
- At 412 GB/s: 8.7 GB / 412 GB/s = 21.1 ms (21.1 ms measured ✓)
- Efficiency near theoretical maximum for streaming weight reads

**Secondary bottleneck: LM_Head** (2.88 ms, 100% BW)
- Reads 1271 MB of INT8 weights per token generation
- Perfect streaming: fully saturates B60 memory BW
- Important: every token requires one LM_Head call regardless of KV length

**PA grows with context**: beyond KV=32K (9.4 ms), PA starts matching small FC ops; at KV=131K it contributes 36.3 ms (53% of the FC contribution).

### 6.2 Prefill Bottlenecks

**S < 32K: Compute-bound (INT8 XMX)**
- FC INT8 dominates at ~67-70% of INT8 XMX peak
- GDN contributes 20% at S=1024 due to recurrent state operations

**S ≥ 32K: PA (O(S²)) starts dominating**
- At S=65K: PA=40%, FC=48%, GDN=12%
- At S=131K: PA=40%, FC=54%, GDN=6%

**fc_down has lower efficiency** (53.6% at S=1024) due to the "tall+narrow" output shape (N=5120) not fitting INT8 XMX tiling well.

## 8. Comparison with B580 (BMG, theoretical)

The B60 has the same Xe Core count as B580 (20) but lower clock (2400 vs 2850 MHz):
- FP16 XMX: B60=98.3 vs B580=116.7 TFLOPS (B60 is 84.2% of B580)
- BW: B60=451 vs B580=456 GB/s (B60 is 98.9% of B580)

**Decode**: Memory-bound ops (FC) scale with BW → B60 ≈ B580 for decode
**Prefill**: Compute-bound ops (FC) scale with TFLOPS → B60 ≈ 84% of B580 for prefill

Expected decode tokens/sec on B580: ~30.6 × (456/451) = **30.9 tok/s** (virtually identical)  
Expected prefill throughput on B580: ~2185 × (116.7/98.3) = **2595 tok/s** at S=2048 (15% faster)

## 9. Key Findings & Optimization Opportunities

1. **B60 memory bandwidth is excellent**: Decode FC achieves 89-100% of 451 GB/s, limited only by paged access patterns for PA and tile alignment for smaller matrices (fc_o).

2. **fc_o has lower efficiency (73%)**: The 6144→5120 (K→N) shape at M=1 is less bandwidth-friendly. Investigate if tiling or subgroup tuning can improve this.

3. **Dense FFN dominates decode** (64.5%): With 65 layers each reading 44.6 MB gate+up+down = 8.7 GB per token, the bottleneck is fundamental to the architecture. Quantizing to INT4 g=128 is already optimal.

4. **LM_Head at 100% efficiency**: The 1271 MB INT8 weight is large enough to guarantee perfect streaming. This 2.88 ms per token is unavoidable without further LM head compression.

5. **GDN prefill at 20% at S=1024**: The recurrent state update pattern in GatedDeltaNet creates sequential memory access patterns. This may be reducible by parallelizing state updates across blocks.

6. **PA becomes dominant at S≥32K prefill**: The O(S²) attention computation exceeds FC cost at large contexts. Flash-attention style block tiling and sparse attention could help for very long contexts.

7. **PA decode remains small at short KV**: Up to KV=8K, PA is <6% of decode time and not a bottleneck. The switch to `paged_attention_opt__gqa_single_token` GQA kernel at KV≥4096 shows the runtime has GQA-aware optimization.
