# Fast top-k 后 QSA 七尺寸完整重测（仅性能测量，尚未计算新 roofline）

## 范围、时间与证据

本轮实际重新执行 **14 个形状 × 2 个 cache 协议 = 28 BENCH，560 个完整 slice，6960 个 GPU events**。
每组 **100 warmup + 20 samples**；没有复用、缩放、外推任何历史时间，也没有删除离群样本。
GPU 仅为 `openvino-ci-74@10.239.140.245` 的 Intel Arc B580；远端工作目录 `/mnt/river/qsa/cm_kernel`。
正式 sweep 为远端 **2026-09-11 00:14:30–00:18:38 +08:00**，即 **2026-09-10 16:14:30–16:18:38 UTC**。

正式原始日志目录：`long_context_fast_topk_logs_rerun_20260910T1614Z/`。
其中 `{prefill,decode}_{1024,2048,4096,8192,16384,32768,65536}.log` 共14份；
每份包含该形状 cold96MiB 和 no-flush 两组原始 JSON，按 `BENCH.cache` 区分。
另有 `protocol_json/{phase}_{size}_{cache}.json` **28份按形状/协议拆分的JSON**，
保留共享 ENV/PLAN/WORK/PASS/HISTORY、该协议的单个BENCH及原log SHA256；不是额外测量或新样本。
`run.log` 保存实际命令策略、起止时间、逐形状 SHA256 与前后 GPU 空闲检查。

初次 `long_context_fast_topk_logs/` 在完成 prefill1024 后检测到新出现的 GPU handle 而停止。
调查确认是 `opencl-language` 服务，所有 DRM engine cycles 均为0；没有终止任何用户进程。
初次日志完整保留但**不纳入结果**，正式目录从第一个形状起全部重跑。
正式 sweep 全程持有 `.qsa_gpu.lock`；每个形状前后共28次检查该服务 cycles 仍全部为0，其他 GPU 使用者均触发停止。
没有并发 GPU benchmark；后续回归也串行执行。

## 固定显式策略，不是新的自动 dispatcher

模型几何保持 D2560、Hq24/Hkv2、Dh/Dv256、Hidx4/Di128/rot32、r4/PA16、K512、gated causal。
全部 B1；prefill 为 `past=0,q=size`，decode 为 `past=size,q=1`。

- prefill1024/2048：CLI `legacy`，实际 `qsa_topk_cooperative`、WG8，dense bypass。
- prefill4096/8192/16384/32768：CLI `fast`，实际 `qsa_topk_radix_fast`、LWS1、CAP256。
- prefill65536：CLI **`fast-wg16`**，实际 `qsa_topk_radix_wg`、LWS16。
- decode1024/2048：CLI `legacy`，实际 old cooperative WG16，dense bypass。
- decode4096/8192/16384/32768/65536：CLI **`fast-wg16`**，实际 `qsa_topk_radix_wg`、LWS16。
- 所有 Q1 为 DPAS projection + prepare；prefill Q2 score 为 DPAS，decode 为 partition16。
- **Q3 完全保持原策略**：prefill GQA-W4；decode1024 scalar；decode≥2048 split-P16 + reduce。
  1024→2048 decode 时间下降包含该既有分派切换，不能解释为单一内核的长度曲线。

通过 ENV.argv、PLAN/BENCH 实际事件名、当前 `finalizer_spec` 和 chunk plan 重建核对有效分派。
WG16 日志明确为 `Q2-fast-WG16`，没有使用会继承 prefill WG8 的含糊 `fast-wg` 别名。
本轮是指定策略的单路径重测，**不是同输入旧/新 A/B**，不据此推断新 crossover 或最优策略。
prefill4K、decode4K/8K 是本轮实际测得的显式策略点，不声称未经 A/B 比较即证明最优。
所有原 benchmark、helper、kernel、默认策略均未修改。

## 计时与正确性契约

使用未修改的 `benchmark_long_context.py`，每个形状通过 BatchMode SSH、
`env CM_FE_DIR=/mnt/river OPENBLAS_NUM_THREADS=1 timeout 900 .venv/bin/python` 执行。
可复现的全部14条形状/策略组合由日志目录内 `run_measurements.sh` 固定；脚本拒绝覆盖已有日志。

- 每组100次 warmup **不 flush**。cold96MiB 的20次正式 sample 各在整个 slice 前 flush 96MiB，
  flush 自身有独立 finish 且不计时。这保持历史 long-context 驱动协议，**不是**
  `benchmark_topk_pipeline.py` v2 的 cache-matched warmup。no-flush 不保证输入必然驻留 cache。
- 顺序固定 prefill升序→decode升序；每个形状 cold→no-flush。两协议各重新 warmup100次。
- GPU sum 是每个 sample 内所有 OpenCL event duration 的和；Q2 累加所有 chunk，Q3 累加 producer/reduce。
  host 是 enqueue→finish elapsed，包含 dispatch/同步间隙；GPU sum 不包含 event 间隙，不是首尾时间戳跨度。
  mean、median、线性p95均由20个完整样本重算；**不能相加各stage的median/p95来得到总量**。
- JIT、分配、输入、真实历史生成、参考校验、readback、日志输出和 flush 不在 timed slice 内。
  20个正式样本之间没有 readback 或日志输出；每组结束后验证 payload 再开始下一组 warmup。
- 输入 x/K/V/query 是确定性 synthetic external inputs，不是模型 trace；历史 summary **不是随机伪造**。
  decode history 经实际 optimized Q0+DPAS Q1 产生，全部历史投影/iq/raw/summary 与缓存 slots 流式验证。
  64K history 全65536行、16384 summaries通过；其 Q0/project/prepare GPU 为
  0.636875/11.520833/2.708125 ms，仅初始化证据，**不计入 decode 测量**。
- 计时前执行真实完整流水线，流式重算每个 score chunk，验证**全部query** own-score top-k、count和padding。
  dense score poison 保持不变；sparse valid scores 全finite；未使用scratch行做原始bit保持检查。
  NumPy Q2/Q3 采用明确采样（含chunk及dense边界），所有采样选集也零差异；不把采样冒称全量NumPy attention。
- 全部输出和iq逐元素finite、所有suffix guards、split partial finite均通过。
  完整重放及每个cache最后测量payload与计时前结果 `assert_array_equal` 通过；NaN poison 对应相等。
  这不是对每个timed sample保存输出，也不声称所有payload都做了逐byte SHA对比。
  post阶段全selected/count与已验证全行own-score结果精确相同。
- NumPy Q3 固定 atol=rtol=0.002；score固定3e-5/2e-5，无放宽容差。
